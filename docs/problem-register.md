# Complete problem register

This register publishes every documented Glass problem at two levels. The first level is a deduplicated mechanism register so one failure can be followed across several reports. The second level lists every one of the 118 documentary sources classified as containing bug or incident material, with the problem/evidence summary recorded for that source. This prevents a concise mechanism list from silently dropping a report, transcript, or secondary issue carrier.

When a source says a result or diagnosis was verified, that status is retained. When later evidence revises it, the revision is added as a later event rather than used to rewrite the earlier record.



Phase 3 treats the 118 `BUG_OR_INCIDENT` documents as historical evidence, not 118 independent defects. The entries below deduplicate overlapping records by observed failure mechanism. “Reported fixed” means only that the cited historical record contains a remedy/result; current survival is intentionally deferred to the current-architecture record.

### `INC-001` — Long-context retrieval and reasoning degradation

- Symptom/evidence: the reports describe lost earlier constraints, fabrication, correction resistance, shallow keyword retrieval, and non-uniform quality across a nominal one-million-token context (`1M_CONTEXT_BUG_REPORT.md:11-218`; `BUG_REPORT.md:10-196`; `docs/2026-3-16/BUG-REPORT-1M-CONTEXT-DEGRADATION.md:1-243`).
- Diagnosis: the observed behaviors are admissible; claims about training length, positional extension, attention mechanics, or vendor incentives are not proven by these project records.
- Attempted remedies/results: proposed earlier compaction, uncertainty calibration, correction weighting, retrieval aids, and disclosure are recommendations rather than verified fixes (`1M_CONTEXT_BUG_REPORT.md:219-543`).
- Successor/unresolved: the issue overlaps Glass recovery and chapter failures below, but the provider-level causal claim remains unresolved.

### `INC-002` — March 24 five-hour quota exhaustion acceleration

- Attempted remedies/results: reports request investigation, credits, and persistence repair; no report proves the vendor-side cause or a durable local fix.
- Successor/unresolved: `5h_RATE_LIMIT_EVIDENCE.md`, `GITHUB_BUG_REPORT_5h_RATE_LIMIT.md`, `RATE_LIMIT_BUG.md`, and `RATE_LIMIT_EXHAUSTION_REPORT.md` reuse substantially the same workload/429 evidence and are not independent corroboration.

### `INC-003` — Deferred compression mutates an already-observed cache prefix

- Successor/unresolved: the local hash/build simulation does not prove Anthropic cache behavior, information-retention quality, or current production wiring.

### `INC-006` — Eviction severs `tool_use` / `tool_result` pairs

### `INC-009` — Chapter archives are either recursively huge or lossy

### `INC-010` — Token accounting and eviction thresholds can be unreachable or misleading

- Symptom/evidence: records alternate among local estimates, provider `cache_read + input`, displayed percentages, a 300k trigger, and observed client/backend ceilings (`text-GLASS-12.md:1-1000`; `text-GLASS-14.md:1-1000`; `text-GLASS-16.md:1-1000`).

- Attempted remedies/results: lower triggers, `LastAPIInput`, headroom, and mode-specific budgets were tried; transcripts disagree on the correct ceiling and do not prove a universal threshold.
- Successor/unresolved: the current-architecture record must trace each provider lane’s authoritative budget and observed-input feedback.

### `INC-011` — Rolling summarizer blocks, loops, or sends invalid requests

- Symptom/evidence: synchronous chunking stalls the request path and later recovery loops persist (`text-GLASS-17.md:1-1000`); repeated fast summarizer HTTP 400s are captured at `text-GLASS-CACHE_BREAK-4.md:61-70`.
- Diagnosis: distinct historical causes include synchronous placement, an unset model/config path, and forwarded beta/auth/request-shape uncertainty. They must not be collapsed into one proven cause.
- Attempted remedies/results: goroutine execution, configured model wiring, and beta hypotheses were tried; `text-GLASS-TENGU.md:1-617` reports a later model/config fix, while other records still show 400s.
- Successor/unresolved: current model, auth header, beta set, request schema, retry behavior, and blocking boundary need direct verification.

### `INC-012` — Global serializer starves concurrent sessions

- Symptom/evidence: second sessions historically wait tens of seconds to the 120-second queue timeout while subagent traffic keeps the active parent’s activity and in-flight count nonzero (`text-MC-FIX-CACHE-BREAK.md:1-1000`); separate traces report 40–250 seconds between ingestion and response despite low provider TTFT (`text-GLASS-16.md:1-1000`).
- Diagnosis: parent-affinity subagents created priority inversion in batch switching; in other periods the serializer was already disabled, invalidating serializer-based explanations (`text-GLASS-BACK2RESEARCH-5.md:1-1000`).
- Attempted remedies/results: separate subagent-in-flight tracking reduced starvation but was followed by increased cache switching/burn in the same transcript.
- Successor/unresolved: latency and cache economics are coupled; neither “always serialize” nor “disable it” is proven generally correct.

### `INC-013` — Subagent cache entries interfere with parent/message-prefix reuse

- Symptom/evidence: incident records show small-system/agent-tool requests near large parent cache-read collapses and competing prefixes (`docs/2026-3-14/BURN_RATE_ROOT_CAUSE_AND_PRIME_GOLDEN_TESTS.md:1-129`; `text-GLASS-BACK2RESEARCH-4.md:1-1000`).
- Diagnosis: provider slot/LRU claims remain partly inferential, but unique subagent message checkpoints are a credible source of cache pressure.
- Attempted remedies/results: historical changes alternately isolated lanes, used parent affinity, disabled upstream cache, gated subagents, or proposed retaining only shared system/tools checkpoints. Several transient improvements were later falsified by wider windows.
- Successor/unresolved: the final `text-MC-FIX-CACHE-BREAK.md:1-1000` recommendation—shared prefix cached, subagent messages uncached—was not implemented/proven there.

### `INC-014` — Conversation identity collapses sessions when PID/parent context is absent

### `INC-015` — Repeated `small_system` traffic has pathological cache policy

## Phase 3 duplicate and contradiction adjudication

- The four public-facing March 24 quota reports share the same 429/workload/cache tables; they count as one evidence family, not four confirmations. The anchor-persistence diagnosis is an added claim, not a property of the shared rows.
- `text-GLASS-1.md` through `text-GLASS-FULLYFUCKED.md` form one evolving eviction/chapter/validation incident chain. Later transcripts frequently falsify earlier “fixed” labels.
- `text-GLASS-BACK2RESEARCH*.md`, `text-GLASS-CACHE_BREAK*.md`, and `text-GLASS-REASON-QUOTA-BURNS*.md` overlap one cache-burn inquiry. Their valid lineage is hypothesis evolution: interleaving/slot assumptions → same-conversation prefix mutation evidence → controlled compression/anchor separation → eager pre-first-send proposal. They are not additive independent root causes.
- `text-GL-CX*.md`, `text-GLASS-CODEX*.md`, and the OpenAI/OMP transcripts distinguish three different surfaces: native Codex Responses transport, OpenAI-compatible local inference, and shared debug/control-plane output. A fix in one is not parity in the others.
- `text-GLASSDD-1.md` is a gap survey; `text-GLASSDD-2.md` is an implementation attempt. The second does not erase its own timeout/default-off/end-to-end gaps.
- Generated synthesis documents remain lineage indexes only. Phase 3 uses their named original sources, not their confidence labels, as evidence.
